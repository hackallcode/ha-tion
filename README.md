# Tion Home Assistant

Интеграция для управления бризерами Tion и чтения показаний датчиков (включая станцию MagicAir) в Home Assistant через облако Tion MagicAir.

Форк с полностью переписанной архитектурой (v2.0.0): облачный клиент вшит в компонент (async/aiohttp), настройка через UI, устройства сгруппированы. Подробности изменений - в [CHANGELOG.md](CHANGELOG.md).

> **Требуется шлюз MagicAir.** Управление идёт через облако Tion (`cloud_polling`), локального доступа нет.

## Возможности

- Бризер: скорость (ручная 1-6 / авто), нагреватель и целевая температура, вкл/выкл, ограничение скорости от/до, забор воздуха, подсветка, звук, сброс ресурса фильтра.
- Станция MagicAir: CO₂, температура, влажность, PM (если модель поддерживает), авторежим зоны, целевой CO₂, подсветка.
- Расписание и пресеты по комнатам: индикация, применение, полный CRUD через сервисы.
- Диагностика: наработка, ресурс фильтра, температуры плат, уровень сигнала, MAC, прошивка.

## Установка

### HACS
1. HACS -> ⋮ -> Custom repositories.
2. Добавьте `hackallcode/ha-tion`, категория `Integration`, сохраните.
3. Установите интеграцию Tion, перезапустите Home Assistant.

### Вручную
Скопируйте `custom_components/tion` в `config/custom_components/tion` и перезапустите Home Assistant.

### Настройка
- **Через UI (рекомендуется):** Настройки -> Устройства и службы -> Добавить интеграцию -> Tion -> введите e-mail и пароль от аккаунта MagicAir.
- **Legacy YAML:** старый блок `tion:` в `configuration.yaml` автоматически импортируется в config entry при старте, после чего блок и секреты можно удалить.

## Устройства и сущности

Устройства зоны (Авторежим, Расписание и т.п.) привязаны к «представителю» зоны - обычно это станция MagicAir.

### Станция MagicAir
| Сущность | Тип |
|---|---|
| CO₂, температура, влажность | sensor |
| PM1 / PM2.5 / PM10 | sensor (только если станция их отдаёт) |
| Уровень сигнала (Wi-Fi), прошивка, MAC | sensor (диагностика) |
| На связи | binary_sensor |
| Подсветка | switch |

### Бризер
| Сущность | Тип | Примечание |
|---|---|---|
| Бризер | climate | скорость `auto`/`1`-`6`, режим `off`/`fan_only`/`heat`, целевая температура |
| Питание, Подсветка, Звук | switch | |
| Мин. скорость (0-6), Макс. скорость (1-6) | number | |
| Забор воздуха | select | 4S: улица / рециркуляция; 3S: квартира / смешанный / улица |
| Нужна замена фильтра | binary_sensor | |
| Температуры входящего/исходящего воздуха, скорость, ресурс фильтра (дней), наработка, мощность нагревателя, темп. плат, сигнал, прошивка, MAC | sensor | часть - диагностика |
| Турбо-режим, «Турбо: прошло» | binary_sensor / sensor | выключены по умолчанию (турбо не поддерживается облаком у ряда моделей) |

### Зона (комната)
| Сущность | Тип | Примечание |
|---|---|---|
| Авторежим | switch | авто/ручной режим зоны |
| Целевой CO₂ | number | 500-1500 ppm, работает в авторежиме |
| Расписание | switch | см. раздел ниже |
| Применить расписание | button | см. ниже |
| Синхронизировано | binary_sensor | следует ли устройство расписанию сейчас |
| Текущий пресет | sensor | имя активного по расписанию пресета |

## Управление расписанием

Расписание и пресеты привязаны к **комнате (зоне)**. Контролы:

- **switch «Расписание»** - вкл/выкл работы по расписанию.
  - Выключение работает.
  - ⚠️ **Включить из HA нельзя** - в облачном API нет метода включения (он есть только в мобильном приложении MagicAir). При попытке включить переключатель вернётся в положение «выкл» и в лог запишется предупреждение. Включайте расписание в приложении.
- **button «Применить расписание»** - пересинхронизация: берёт пресет, который расписание должно применять сейчас, и пушит его настройки на бризер (аналог кнопки «применить настройки расписания» в приложении, когда вы вмешались вручную). Флаг `is_mode_sync` в облаке при этом может не измениться - он тоже мобильный.
- **binary_sensor «Синхронизировано»** - показывает `is_mode_sync`. Если `off` - устройство отклонилось от расписания, можно нажать «Применить».

Создание и редактирование самого расписания и пресетов - через сервисы `tion.*` (ниже).

## Сервисы

Все сервисы таргетируют **устройство** (`device_id`) - любое устройство Tion нужной зоны; зона определяется автоматически.

| Сервис | Назначение |
|---|---|
| `tion.get_presets` | получить список пресетов зоны |
| `tion.set_preset` | создать (без `guid`) или изменить (с `guid`) пресет |
| `tion.delete_preset` | удалить пресет по `guid` |
| `tion.get_schedule` | получить расписание зоны |
| `tion.set_schedule` | создать (без `guid`) или изменить (с `guid`) расписание |
| `tion.delete_schedule` | удалить расписание |

> ⚠️ **Важно про удаление.** На стороне облака Tion удаление расписания или пресета **каскадом стирает все пресеты зоны** (проверено). Сервисы `delete_schedule` и `delete_preset` в этой интеграции **защищены**: перед удалением снимается снапшот пресетов и расписания, а после - всё, что снёс каскад, автоматически пересоздаётся; удалённым остаётся только тот объект, который вы просили удалить. Пересозданные пресеты получают новые `guid`, поэтому расписание при необходимости перенацеливается по именам.

### Примеры (Инструменты разработчика -> Действия)

Создать/изменить расписание (`starts_at` - секунды от полуночи):

```yaml
action: tion.set_schedule
data:
  device_id: <id_устройства_зоны>
  schedule:
    active_days: [mon, tue, wed, thu, fri, sat, sun]
    timings:
      - preset_id: <guid_пресета>   # из tion.get_presets
        starts_at: 25200            # 07:00
      - preset_id: <guid_пресета>
        starts_at: 82800            # 23:00
```

Создать пресет:

```yaml
action: tion.set_preset
data:
  device_id: <id_устройства_зоны>
  preset:
    name: Ночь
    icon: 0
    climate_settings:
      mode: auto        # auto | manual
      co2: 600
    devices:
      - id: <guid_бризера>
        speed: 0
        speed_min_set: 1
        speed_max_set: 2
        t_set: 10
        is_on: false
        gate: 0
        heater_mode: maintenance   # heat | maintenance
```

Для редактирования добавьте `guid` (пресета/расписания) в объект - интеграция сделает PUT вместо POST.

## Ограничения (облачного API, не приложения)

- **Включение расписания** - только в приложении MagicAir (см. выше).
- **Турбо-режим** - не активируется через облако у ряда моделей (у 4S его нет); соответствующие сущности выключены по умолчанию.
- **Забор воздуха** зависит от модели: у 4S два положения (улица/рециркуляция), у 3S - три.
- **Целевой CO₂** - допустимый диапазон 500-1500 ppm.
- Пресетов - **не более 5 на зону**.

## Если что-то не работает

Включите подробное логирование в `configuration.yaml`:

logger:

  logs:
